# SueldoNeto 2.0 — Plan de dominio único con SEO programático + lead-gen

> **For Hermes:** Use subagent-driven-development skill to implement this plan task-by-task.

**Goal:** Convertir SueldoNeto.ar de 24 páginas estáticas en un activo programático de ~1.000 páginas long-tail con monetización por afiliados fintech + datasets citables + API, apuntando a $800–2.500/mes en 18 meses y un activo vendible a 30–40×.

**Architecture:** Next.js 16 App Router estático (SSG) en Cloudflare Pages. Un motor de rutas dinámicas con `generateStaticParams` reutiliza las calculadoras puras de `src/lib/`. Crons existentes (patrón fetch-anses + auto-PR de Maternidad) refrescan datos ARCA/BCRA que inyectan contenido único y viviente en cada página. AdSense como piso, lead-gen fintech como motor.

**Tech Stack:** Next 16.3, React 19, Tailwind 4, Vitest, Cloudflare Pages, GitHub Actions (crons + deploy), datos BCRA/ARCA/INDEC vía API pública.

---

## Contexto y decisiones estratégicas (por qué este diseño)

1. **50 dominios nuevos es una trampa.** 50 autoridades en cero vs. el fresh-domain filter. El SEO programático funciona sobre UN dominio con edad y autoridad (modelo SmartAsset: 1,1M keywords, exit $1B).
2. **AI Overviews mataron el texto, no las tools.** CTR de definiciones −59%, de informativas −37%; transaccionales/herramientas −10% (datos T1 2026). Todo el plan apunta a páginas-herramienta con intent exacto.
3. **Anti-penalidad es un requisito de diseño, no un parche.** El core update de marzo 2026 quitó 60–80% de tráfico a sitios con 500+ páginas AI delgadas, estructura idéntica y sin datos propios. Contramedidas integradas al motor:
   - Cada página renderiza **resultados calculados reales** (únicos por definición) + tablas + FAQ.
   - Párrafos generados por **composición de variantes** (≥6 oraciones × 3 posiciones por banda de monto) → cero estructura idéntica.
   - **Datos vivos** (IPC mensual, tramos ARCA vigentes) en cada página → se actualizan solas cada mes.
   - **Release en tandas de 100/mes**, nunca 1.000 de golpe. Sitemap segmentado.
   - Páginas interlinkadas en clúster (hermana anterior/siguiente + calculadora madre).
4. **Lead-gen sobre Adsense:** un registro fintech paga $5–30 = 2.500–15.000 pageviews de Adsense. Conversión objetivo 0,2% (1 cada 500 visitas) — alcanzable con un CTA honesto.
5. **Salida:** portfolio facturando $1.500/mes se vende a ~$50k (30–40×). "Vivir de esto" = evento de venta a 24–36 meses, no sueldo mensual.

### Números objetivo (conservador → realista)

| Etapa | Páginas | pv/mes | Ingreso |
|---|---|---|---|
| Mes 6 | 300 | 15.000 | $150–400 |
| Mes 12–18 | 1.000 | 150.000 | $800–2.500 |
| Mes 24+ | 2.000+ | 400.000 | $3.000–8.000 (venta: $50k+) |

**Break-even del proyecto: ~1.500 pageviews/mes totales** (costo marginal ≈ $0; dominio ya pagado hasta 8/2027).

## Riesgos y mitigaciones

| Riesgo | Mitigación |
|---|---|
| Scaled content abuse (marzo 2026 penalizó 500+ páginas delgadas) | Resultados calculados únicos + variantes + datos vivos + tandas de 100 + >300 palabras reales |
| Desindexación de tanda | Meta de indexación 60%/30d; si no, pausar y diagnosticar antes de más tandas |
| Rechazo AdSense en programas delgados | El dominio ya tiene contenido real (14 calculadoras + guías); solicitar tras tanda 1 con hub |
| Cambio de APIs BCRA/ARCA | Patrón fallback ya probado en Maternidad (Jina bare) + alerta en cron |
| Términos de afiliados cambian | Fecha de verificación en `fintech.json`, revisar en cron semestral |
| Canibalización con /calculadora-sueldo | Canonical: hub deja de competir; cada página [monto] se enfoca en el long-tail exacto |
